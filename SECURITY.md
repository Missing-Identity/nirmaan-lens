# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a vulnerability involving private-document exposure, authentication, cross-user access, source poisoning, prompt injection that changes tool behavior, or a bypass of citation/safety gates.

Until a dedicated security contact is published, use GitHub's private vulnerability reporting feature for this repository.

Include:

- affected component and version;
- reproduction steps using non-sensitive test data;
- potential impact;
- suggested mitigation if available.

Do not include real property documents, credentials, direct personal identifiers, or portal access tokens.

## Supported versions

The project has not released a production version. Security fixes will target the default branch until a formal support policy is established.

## Safety issues versus vulnerabilities

Unsupported answers, incorrect citations, temporal mistakes, and unsafe confidence should be reported as safety/quality issues unless they enable unauthorized access, data exposure, policy bypass, or corpus manipulation.
